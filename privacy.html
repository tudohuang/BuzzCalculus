隱私政策

最後更新：2026-08-17

這一頁描述 BuzzCalculus 實際上做了什麼，不是一份通用範本。 每一條都對應得到程式碼裡的一個位置。

一句話版本

你的練習紀錄只存在你自己的瀏覽器裡。我們沒有帳號系統，沒有伺服器資料庫， 也拿不到你的作答內容。唯一會離開你裝置的，是匿名的使用計數，而且你可以關掉。

存在哪裡

全部在這台裝置的瀏覽器儲存空間裡：

  • localStorage —— 練習紀錄、錯題本、進行中的存檔、自訂題目、外觀設定。
  • IndexedDB —— 黑板的手寫草稿（重做錯題時可以看上次怎麼算的）。

這代表兩件事：換一台裝置就是全新開始（我們無法幫你救回來）， 以及清掉瀏覽器資料就等於刪除全部紀錄。

會離開裝置的東西

1. 使用分析（可關閉）

我們用 Google Analytics 4 記錄「哪個功能被用了幾次」，例如開始一局、送出答案、 打開提示、完成一局。事件裡帶的是模式名稱、題目難度、花費秒數這類欄位。

送出去的內容不包含你輸入的答案、題目內容、草稿，或任何可以辨識你的東西。 這條規則由自動化測試把關（tools/validate_analytics.js 會掃描所有事件， 發現夾帶使用者輸入就讓建置失敗）。

在設定頁可以關閉。關閉之後連 Google 的分析程式都不會載入—— 不只是不送事件，是連那一支 script 的請求都不會發出。

2. 難度校準包（預設關閉，要你主動按）

如果你願意幫忙修正題目難度，可以在設定頁匯出一份統計檔。裡面只有： 永久題號、難度等級、答對／答錯次數、中位作答秒數，以及你的整體程度分層（高／中／低）。

沒有題目內容、沒有作答內容、沒有時間戳記，自訂題一律排除。 按下匯出之前可以先按「先看內容」——顯示的就是實際會產生的那份檔案本身， 不是另外寫的說明文字。

這是一個檔案下載。要不要把它寄給我們，完全由你決定。

3. 當機回報（跟著使用分析一起開關）

程式出錯的時候會送一筆事件，讓我們知道有東西壞掉了。裡面只有三樣： 錯誤型別（例如 TypeError）、哪個檔案的第幾行、 以及你當時在哪個畫面。

錯誤訊息本身與堆疊追蹤一律不送。 因為 JavaScript 的錯誤訊息常常會把變數的值印進去， 而那可能是題目、你輸入的答案或存檔片段。這條規則同樣由 tools/validate_privacy.js 把關 —— 程式碼裡只要碰到 .message 或 .stack，建置就會失敗。

關閉使用分析之後，當機回報也一起停止。

4. 回報題目（你按下去才會發生）

按「回報」不會把任何東西送出去。它會把題號、題目、參考答案、問題類型與版本 整理成一段文字，攤在你眼前，然後由你決定要開 GitHub issue 還是複製走。

選擇開 issue 的話，內容會出現在 GitHub 上的公開頁面，並適用 GitHub 自己的隱私政策。 不想公開就用「複製內容」，要不要寄、寄給誰都由你決定。

5. 靜態資源

網站本身由 GitHub Pages 提供。數學排版、圖示與動畫的程式庫都已經打包在站內， 不會向第三方 CDN 發出請求。

我們沒有做的事

  • 沒有帳號、沒有密碼、沒有 email 收集。
  • 沒有廣告，沒有廣告追蹤碼。
  • 不販售、不交換任何資料。
  • 沒有伺服器端的使用者資料庫 —— 我們沒有東西可以外洩。

怎麼刪除

設定頁 →「清除資料」。它會刪掉：

  • 練習紀錄與錯題本
  • 進行中的存檔
  • 自訂題目
  • 黑板手寫草稿（IndexedDB）
  • 外觀與同步設定

刪除前會列出實際會刪掉的數量，並且要再確認一次。 這個動作無法復原——沒有雲端備份可以還原。想留一份請先匯出 JSON。

已經送出的匿名分析事件無法逐筆刪除（它們本來就無法對應到任何個人）。 要停止繼續送出，請在設定頁關閉使用分析。

兒童

這個工具給正在學微積分的人使用，不特別針對兒童設計，也不會主動收集年齡。

變更

這一頁如果有實質變更，會更新上方的日期。因為沒有帳號，我們沒有辦法主動通知你。

聯絡

有問題或想回報資料處理上的疑慮，請透過專案的 GitHub issue 反映。

Privacy Policy

Last updated: 2026-09-30

This page describes what BuzzCalculus actually does; it is not a generic template. Every item maps to a place in the code.

In one sentence

Your practice records exist only in your own browser. There are no accounts and no server database, and we can't see your answers. The only thing that leaves your device is anonymous usage counts, and you can turn those off.

Where things are stored

Everything is in this device's browser storage:

  • localStorage: practice records, mistake notebook, in-progress saves, custom problems, appearance settings.
  • IndexedDB: handwritten scratch work (so you can see how you worked a problem last time).

Two consequences: a new device is a fresh start (we can't recover anything for you), and clearing browser data deletes all your records.

What leaves your device

1. Usage analytics (can be turned off)

We use Google Analytics 4 to count how often features are used: starting a session, submitting an answer, opening a hint, finishing a session. Events carry fields like the mode name, the problem's difficulty, and seconds spent.

What is sent never includes the answers you type, problem content, scratch work, or anything that identifies you. An automated test enforces this (tools/validate_analytics.js scans every event and fails the build if user input slips in).

You can turn it off in Settings. Once off, the Google analytics script isn't even loaded: not only are no events sent, the request for that script is never made.

2. Difficulty calibration pack (off by default; only when you click)

If you'd like to help fix problem difficulty, you can export a stats file from Settings. It contains only: permanent problem numbers, difficulty ranks, right/wrong counts, median answer time, and your overall level band (high / middle / low).

No problem content, no answers, no timestamps, and custom problems are always excluded. Before exporting you can click "Preview first": what it shows is the actual file that will be produced, not a separate description.

It is a file download. Whether to send it to us is entirely up to you.

3. Crash reports (on/off together with analytics)

When something breaks, one event is sent so we know. It holds only three things: the error type (e.g. TypeError), the file and line number, and which screen you were on.

The error message and stack trace are never sent. JavaScript error messages often print variable values, which could be a problem, your answer, or part of a save. tools/validate_privacy.js enforces this too: any code that touches .message or .stack fails the build.

Turning off analytics also turns off crash reports.

4. Reporting a problem (only when you click)

Clicking "Report" sends nothing. It gathers the problem number, the problem, the reference answer, the issue type and the version into a block of text, shows it to you, and lets you choose whether to open a GitHub issue or copy it.

If you open an issue, its content appears on a public GitHub page under GitHub's own privacy policy. If you'd rather not make it public, use "Copy content"; whether and to whom you send it is your call.

5. Static assets

The site itself is served as static files. The math typesetting, icon and animation libraries are bundled with the site, so no requests go to third-party CDNs.

What we don't do

  • No accounts, no passwords, no email collection.
  • No ads and no ad trackers.
  • We don't sell or trade any data.
  • No server-side user database: there's nothing of yours to leak.

How to delete

Settings → "Clear data". It deletes:

  • Practice records and the mistake notebook
  • In-progress saves
  • Custom problems
  • Handwritten scratch work (IndexedDB)
  • Appearance and sync settings

Before deleting it lists how much will be removed and asks you to confirm. This can't be undone: there's no cloud backup. Export the JSON first if you want a copy.

Anonymous analytics events already sent can't be deleted one by one (they can't be tied to anyone in the first place). To stop sending them, turn off analytics in Settings.

Children

This tool is for people learning calculus. It isn't designed for children and doesn't collect ages.

Changes

If this page changes materially, the date above is updated. With no accounts, we have no way to notify you.

Contact

For questions or concerns about data handling, please open an issue on the project's GitHub.
