# 09 — 分期、驗收、指標、風險

## 分期總覽

每一期都是**可獨立上線**的。任何一期做完就停，站台仍然比今天好。

| 期 | 代號 | 主題 | 一句話 |
| --- | --- | --- | --- |
| P0 | 固化 | 把現況鎖住 | 大修之前先讓現在的行為有測試保護 |
| P1 | 收納 | IA + onboarding + 止血 | 讓新使用者進得來、讓老使用者不丟資料 |
| P2 | 診斷 | 能力模型 | 從「正確率」進化到「你是不會還是來不及」 |
| P3 | 內容 | 題庫工業化 | 難度可解釋、答案可驗證、來源可交代 |
| P3.5 | 產品化 | 從「像玩具」到「像軟體」 | 做得好還不夠，要看起來就值得信任 |
| P4 | 帳號 | 雲端 + 法遵 | 一個帳號帶著走 |
| P5 | 社群 | 投稿 + 班級 + 賽季 | 讓內容與動機從外部進來 |
| P6 | 平台 | 多科 + Pro + 英文 | 從產品變成引擎 |

## P0 — 固化（1–2 週）

**目的**：在動任何東西之前，讓「現在的行為」有測試保護。這是整份 spec 唯一沒有新功能的一期。

> **2026-08-16 補完。** 這一期原本被跳過，直接做了 P1–P3；
> 補回來的時候才發現它擋的正是後面那些改動製造出來的風險。

- [x] **三清單一致** —— `validate_app_shell.js`（index.html ↔ sw.js）
      加上 `load_problem_sources.verifyOnly()`（磁碟上的題包 ↔ index.html）。
      另外把 `tools/lib/app_api.js` 改成照 index.html 的**文件順序**載入所有 `src/*.js`：
      順序是有意義的（skill_graph / rubric 必須在難度校準之前），而且原本有四支驗證器
      各自帶假 DOM、只載題庫，測到的是 fallback 路徑 ——「Boss 挑戰」在那裡有 763 題，
      實際上線是 264 題。
- [x] **黃金快照** —— `tools/validate_golden.js`（進 CI）。釘住兩件事：
      難度分佈 + 91 個錨點題的 rank/三軸；以及 kernel 的行為（能力模型、判分器 12 案例、SRS 4 種到期狀態）。
      實測有效：把 ability.js 的半衰期常數從 10 改成 20，黃金檔立刻報出
      `integral.usub: 47 → 50` —— 而其他 20 支驗證器全部照樣是綠的。
- [x] **records 遷移測試** —— 在 `smoke_app_render.js` 裡：v1 history → normalize → schema 2、
      attemptLog 筆數相符、history 不被動到、而且**冪等**（跑第二次 attemptLog 不會再長）。
- [x] **smoke 擴充** —— 首頁 / 訓練 / 數據 / 考後報告 / onboarding / 續傳 / 匯入備份 /
      a11y / 能力快取 / 校準包隱私，每一項都會 render 或驗到不變式。
- [x] **版本號統一** —— 當時是 `v0.21.0-beta`（2026-08-17 起為 `v1.0.0`），`tools/validate_version.js` 進 CI。
      原本三個地方三個答案（app.js v0.9.12 / README v0.10.0 / sw.js v0.20.0）。
      這不只是難看：`app_version` 會跟著**每一筆分析事件**上報，
      所以整份使用資料都被標上了一個不存在的版本。
- [x] **E2E 主幹** —— `tools/e2e_main_flow.js`，21 項斷言，約 45 秒，進 CI。
      **沒有用 puppeteer-core**：這個專案的工具鏈是零依賴的，為了跑 E2E 長出一個
      node_modules 等於在部署路徑上多開一道供應鏈。Node 22 內建了 WebSocket 與 fetch，
      而 CDP 本身就是「連上 ws、送 JSON」——`tools/lib/cdp.js` 兩百行就夠了。

      斷言的原則是**只斷言使用者實際看得到、點得到的東西**：文字要有面積、
      opacity 不是 0（不是「存在於 DOM」），互動要真的觸發事件委派，
      console 不能有錯、資源不能有 404。

      驗證過它擋得住：把題數改回寫死的 1407、把結算頁的元素設成 opacity:0，
      兩個回歸都被抓出來。

**Exit**：CI 全綠（當時 22 支；目前數量見 [README 現況快照](README.md#現況快照)），且任何人改壞能力模型、判分器、難度、SRS，或讓主流程在瀏覽器裡走不通，都會被擋下。

## P3 — 內容工業化（6–8 週，可與 P2 平行）

> **已完成（2026-08-16）。** 一次全部做完，19 支驗證器全綠。
> 最重要的一項是答案驗算：在它之前，答案的正確性完全靠人工檢查，
> 也就是完全沒有機器把關 —— 而 spec 00 的第一原則是
> 「答案錯一題造成的信任損失，大於新增五十題的收益」。

- [x] **答案獨立數值驗算**（[05.3](05-content-pipeline.md#53-答案驗證)）—— 712 題可驗證、不符 0，CI 擋線
- [x] **永久題號 uid**（[02.3](02-data-model.md#為什麼要-uid-而不是沿用-id)）—— 1456 筆，號碼永不回收
- [x] **rubric 三軸 backfill**（[05.1](05-content-pipeline.md#51-難度-r1r6-正式-rubric)）—— 1420 題，rank 完全不變
- [x] **origin 來源聲明**（[05.4](05-content-pipeline.md#54-來源與原創聲明)）—— 1420 題，名校詞彙偵測進 CI
- [x] **重複偵測**（[05.5](05-content-pipeline.md#55-重複偵測)）—— 抓到 34 組並移除，語意層用數值指紋
- [x] **判分器強化** —— 定義域取樣、`set` / `interval` 兩種新題型 + 10 題示範
- [x] **模板變體管線**（[05.6](05-content-pipeline.md#56-參數變體)）—— 逐題驗算才准寫出
- [x] **難度校準包匯出**（[05.2](05-content-pipeline.md#52-實證校準)）—— opt-in、去識別化、內容可預覽
- [x] **草稿存 IndexedDB** —— 重做錯題時看得到上次的手寫
- [~] **第二層提示 64.0%**（作者 53.7% + 機器推導 10.3%）——
      `tools/lib/hint_facts.js` 從題目本身推出可驗證的事實（0/0 型、King's 常數、
      比值判別的值…），每條都在 CI 重新驗算（[05.7](05-content-pipeline.md#57-推導式提示第二層)）。
      剩下 525 題推不出可驗證的事實，那是人要寫的。
- [ ] **結構化解題步驟 5.6%** —— 機制完成，內容待人工補
- [x] **難度重新分佈** —— R6 32.4% → 5.3%，R5+R6 53.7% → 18.1%。
      做法不是「機器重分配到目標」，是先在 77 個技巧節點上逐一標註冷門度，
      再從題目特徵推三軸。rubric 現在是 rank 的唯一來源，標籤地板退居 fallback。
      降三級以上的 187 題在 `reports/rank-review.json` 等人工複核
- [x] **37 組語意重複已複核**（2026-08-17）—— 結論不是刪掉一邊。
      兩邊通常分屬不同題包（一個入門友善、一個考古題風格），刪任何一邊都會開一個洞。
      真正的傷害是**同一局或同一份考卷抽到兩題一模一樣的** ——
      所以改成把等價關係寫成側表 `src/kernel/equivalence.js`（71 題、35 組），
      抽題與出卷時同一組只准出現一次。內容一題都沒刪。
      其中 2 組判定為**誤判**（∫1/x vs ∫(x+1)/(x²+x)、兩個不同的重積分），
      理由寫在產生器的 `NOT_EQUIVALENT` 裡；那兩組哪天不再被判為重複會被提醒移除。

      這條驗證順手抓到一個真的 bug：`session.fill` 的 `take()` 是在迴圈**開始前**
      算好候選快照，迴圈中加進 `used` 的不會回頭重濾。id 唯一時永遠看不出來，
      換成等價鍵之後同一批候選裡的兩題等價題就雙雙通過了。

## P3.5 — 產品化（2026-08-17 完成 18/20）

> 這一期原本不在 spec 裡。它來自一個很短的觀察：**內容與驗證的品質已經遠遠超前
> 外觀給人的印象。** 問題不是功能不夠，是幾個看得見的訊號正在把一個嚴肅的東西
> 講成一個週末專案 —— 而要收錢的話，那些訊號比再多五十題重要。

**可信度**

- [x] **答案可信度看得見** —— 774 題通過獨立驗算的事實原本只存在於 CI 輸出裡。
      產出 `src/kernel/verified_answers.js` 側表，題目與題庫上標「答案已驗算」。
      沒標的不是「沒驗過就上線」，是**驗不動**（證明題與定性題沒有可比對的數值），
      所以文案不能寫成「未驗證」那種暗示品質不同的說法。
- [x] **拿掉 beta** —— `v1.0.0`。建置日期改由 `tools/stamp_build.js` 從 git 蓋。
      原本是手寫常數，於是它做了所有手寫常數都會做的事：停在兩個月前，
      而那兩個月改了三千多行。訪客第一眼看到的就是那個日期。
- [x] **有人負責** —— `about.html`：作者、題目來源、答案憑什麼可信。匿名工具沒有人推薦。
- [x] **回報送得出去** —— 見 P4。
- [x] **來源透明** —— 「XX 風格」補上「非該校真題」的說明（法律面的暴露，不只是觀感）。
- [x] **更新紀錄** —— `changelog.html`。

**完成度**

- [x] **撤回空頭支票** —— 「雲端同步 · 即將推出」沒有日期，掛越久越像棄坑。
      改成說清楚匯出／匯入現在就能用，以及為什麼還不做帳號。
- [x] **同步合併** —— 見 P4。
- [x] **詞彙統一** —— 同一畫面上「作答歷史 4」與「練習局 0」是兩個不同欄位。
      看到兩個矛盾的數字之後，使用者會開始懷疑**所有**數字，包含弱點分析。
- [~] **渲染** —— 分兩步做，第二步還沒做完。
      1. **止血**：`render()` 之後把使用者感覺得到的三件事接回去 ——
         捲動位置、焦點與游標、展開狀態。
      2. **開路**：`[data-action]` 從「每次 render 把畫面上每一個節點各綁一次」
         改成 `#app` 上的單一委派。**這件事本身幾乎沒有效能收益**（實測題庫頁
         231 個節點只花 0.19ms，而整頁 `innerHTML` 重建是 21ms）——
         它的價值是讓「只換一小塊 DOM」變成可能：新插入的節點不需要重新綁任何東西。
         第一個受益的是計算紙換工具（見下）。

      `render()` 仍然是整頁 `innerHTML`。真正的局部渲染是一次大重構，還沒動。
- [x] **計算紙的局部更新** —— 換筆／橡皮擦、換紙／黑板都不再走 `render()`。
      在這之前換一次工具就是整頁重繪：canvas 被重建、所有筆畫重畫一次。
      寫滿一頁之後那一下看得出來卡，而使用者只是想換個工具。
      `e2e_handwriting` 釘住「換工具時 canvas 必須是同一個節點」。
- [x] **更新體驗** —— service worker 原本部署一次就強制重載所有分頁（模擬考考到一半被刷掉）。
      改成「有新版本」橫幅，作答中不出現，什麼時候更新由使用者決定。

**語氣**

- [x] **遊戲化分層** —— 專注模式收起連勝、盾牌與成就（照算，只是不顯示）。
      學生要動機，研究所考生與家教要工具；付費決策常發生在後者身上。
- [x] **文案校準** —— 專業感來自精確而不是嚴肅。「可以殘忍的地方」→「高難度，有失敗條件」；
      清掉 WebWork 這類對使用者沒有意義的內部術語。
- [x] **資訊密度** —— 寬螢幕首頁兩欄。單欄在 1240px 上有一半是空的，讀起來像「內容不多」。

**認真使用者要的能力**

- [x] **可列印** —— 錯題本「列印／存 PDF」+ 完整 `@media print`。
      紙本是台灣學生真正的複習載體；不做的話使用者會自己截圖，而那個成品不像這個產品。
- [x] **弱點處方** —— 用技能圖的前置關係算出「先回去補 X」。
      「你在勞必達上正確率 62%」是資訊；「先補基本極限再回來」才是產品。
      規則刻意保守：處方給錯比不給更傷信任。
- [x] **出卷** —— 指定範圍／難度區間／題數，可鎖題、換卷、列印。
      **同一組條件永遠抽到同一份**（固定種子）—— 隨機而不可重現的抽卷在教學現場等於不能用。
- [x] **鍵盤** —— 對話框焦點鎖 + Esc。沒有焦點鎖的話 Tab 會走到被遮住的按鈕上，
      而「刪除全部資料」那個對話框後面就是那顆刪除鈕。
- [~] **無障礙** —— 7 個對話框的 aria 與焦點鎖進 smoke。要到「可對外宣稱」
      還需要真的用輔助科技走查，那不是加幾個 `aria-` 就算。

**工程與營運**

- [x] **錯誤遙測** —— 只送型別、檔名、行號、當時的畫面。
      **訊息本體與堆疊一律不送**：JS 的錯誤訊息常把變數值印進去，那可能是題目或使用者的答案。
      `validate_privacy.js` 會擋 `.message` / `.stack`。
- [~] **拆分 `app.js`** —— 抽出 `src/kernel/board_render.js`。
      不是拆完 12000 行 —— 拆到一半比不拆更危險。這一塊的做法是可複製的模板，
      而且 golden 測試用假的 ctx 錄下繪圖指令序列鎖住了它的行為。

**同期的 iPad 手寫**：見 [08.5 階段 0](08-platform.md#85-手寫辨識與筆跡回放)。

**移除的**：全螢幕鎖定與切頁判錯（見 [00 P4](00-north-star.md#p4-焦慮只准存在於考試模式)）。

**Exit**：一個第一次看到這個站的人，在三十秒內找得到「誰做的」「答案憑什麼可信」
「多久更新一次」，而且找不到任何自稱 beta 或停在過去的東西。

- [ ] 後端 6 個 endpoint（[06.2](06-identity-sync-legal.md#階段-b帳號與真同步p4)）
- [x] `merge()` per-key 合併同步 —— 交換律 / 冪等 / 不丟資料由 CI 鎖住。
      **2026-08-17：接進 `syncNow()`。** 在那之前 merge 只用在「匯入 JSON」上，
      同步本身還是整包 LWW —— 兩台裝置都練過就會吃資料，而單一裝置上永遠看不出來。
      現在 pull 之後一律合併，結果先寫回本機再推上去（只推不存的話兩邊不會收斂）。
- [x] **隱私政策 / 服務條款 / 資料刪除** —— `privacy.html` + `terms.html`，
      設定頁可直達；`tools/validate_privacy.js` 進 CI。
      驗證器把「政策寫的」跟「程式碼做的」綁在一起 —— 政策最常見的失敗方式不是寫錯，
      是寫完之後程式碼改了，而沒有任何測試會紅。
- [x] **GA4 關閉開關** —— 關掉之後**連 gtag.js 都不載入**，不只是不送事件。
      光是載入那支 script 就已經帶著 IP 與 User-Agent 對 Google 發出請求了。
      開關存在 records.settings，跟著匯出／匯入走 —— 換裝置還要再關一次的開關等於沒有開關。
- [x] **題目回報送得出去**（2026-08-17）—— 原本 `reportProblem()` 只把一筆紀錄寫進
      **使用者自己的 localStorage** 就結束了：按鈕變成「已回報」，作者永遠收不到。
      那比沒有回報按鈕更糟，它製造了「已經反映過」的錯覺。
      改成把題號／題目／參考答案／問題類型整理成一段文字**攤在使用者眼前**，
      再由他決定開 GitHub issue 還是複製走 —— 沒有伺服器也送得出去，
      而且不違反「沒有伺服器收你的資料」這句承諾。
- [ ] 自動 quarantine（同一題被回報 N 次就下架待審）—— 需要能收集回報的那一端
- [ ] 校準資料自動上報（opt-in）→ 第一次真正的實證難度校準

**Exit**：
兩台裝置交叉練習後同步，作答總數不減少（`merge` 冪等 + 交換律測試）；
帳號刪除流程可端到端跑完；同步失敗時本機資料永遠不受損。

| 風險 | 影響 | 機率 | 對策 |
| --- | --- | --- | --- |
