# 04 — 體驗與資訊架構：收納、開局、Session 引擎

## 4.1 診斷：現在的問題是「太多」

實測目前有 **19 個練習模式**、**46 個訓練題包**、10 個主線關卡、多張具名模擬卷。

```text
MODES: quick topic daily practice brutal boss boss_rush rival daily_one exam
       integral_bee no_hint accuracy survival warmup cooldown mistakes placement weekly
PACKS: 51 個（todai_burst / nightmare_boss / world_universities / competition /
       damo_longform / putnam / beginner_warmup / … / chem_memory）
```

這些**全部都是好東西**，問題不在內容，在**入口**。新使用者第一次進站要面對 1407 題 × 19 模式 × 46 題包
的組合空間，沒有人做得出決定。

**P1 的工作是收納，不是刪除。一個模式都不砍。**

## 4.2 模式分類法

> **實作現況（2026-08-16）**：`MODES` 的 19 個模式都已加上 `bucket` 欄位
> （practice 7 / weakness 1 / exam 2 / challenge 9），純加欄位、零行為改變。
> smoke test 會擋住漏標或標錯 bucket 的模式。UI 的四分類收納尚未做。

在 `MODES` 每一項加一個 `bucket` 欄位（純加欄位，零破壞），分四類：

| bucket | 中文 | 成員 | 特徵 |
| --- | --- | --- | --- |
| `practice` | 練習 | quick, topic, practice, warmup, cooldown, no_hint, placement | 學東西的地方。**不得製造焦慮** |
| `weakness` | 弱點 | mistakes（SRS 錯題）, 弱點練習, 危險技巧練習 | 系統挑題，使用者不選 |
| `exam` | 模擬 | exam, 期中/期末/大考/轉學考 named exams, weekly | 高壓規則只准在這裡：整份倒數、無提示（監考類規則已移除） |
| `challenge` | 挑戰 | boss, boss_rush, brutal, rival, integral_bee, survival, accuracy, daily_one, daily | 玩的地方。可以殘忍 |

UI 上這四類是**四張卡**，不是 19 個按鈕。每張卡點進去才展開內含模式。

同樣地，46 個題包依 `PACK_GROUPS` 收成分組（此結構已存在），
在「練習 → 指定技巧」下才出現，首頁不出現。

## 4.4 Session 引擎

> **實作現況（2026-08-15，kernel 已上線，UI 尚未接）**
>
> `src/kernel/planner.js`（決定練什麼）+ `src/kernel/session.js`（實際抽題）
> + `tools/validate_planner.js`（已進 CI，7 種使用者 × 3 種長度全覆蓋）。
> `today() + fill()` 約 3ms。
>
> 三處與原設計的差異，都是實測時被打臉才改的：
>
> 1. **題數是動態的，不是固定 6 / 12 / 26。** 原設計寫死題數，實測發現一個
>    「弱點落在 R5 長題」的使用者，daily15 的 12 題實際要做 **28 分鐘**。
>    標榜 15 分鐘卻給 28 分鐘比不標時間更傷信任。
>    改成：planner 依候選題的實際 `timeLimit` 中位數推題數，
>    **`session.fill` 再對時間預算負最終責任**（超過就從最不關鍵的角色開始砍，
>    不足就補）。砍題順序：filler → boss → hard → stretch → warmup →
>    maintain → new → weak → review —— 到期複習與弱點是這次訓練的目的，最後才動。
> 2. **`why` 不寫題數。** 配方產生之後 fill 還會增減題目，寫死題數會和使用者
>    實際看到的對不起來。題數由 UI 讀 `fill` 的結果顯示。驗證器會擋住。
> 3. **`fill` 不做科目閘門與難度上限過濾。** 那些規則歸 app.js，
>    傳進來的 pool 就已經是合法候選集。kernel 不重複實作一份會漂移的規則。
>
> **「有效訓練」有了可驗證的定義**：`planner.isEffective()` ——
> 至少涵蓋 2 個弱點技巧、且至少 3 題到期複習。沒有這個定義的話那只是行銷詞。
>
> **已接上**：首頁「今天的訓練」卡片（見 [4.3](#43-首頁重構)），實測可直接開局。

### 三種長度

| key | 名稱 | 時間 | 題數 | 組成 |
| --- | --- | --- | ---: | --- |
| `sprint5` | 5 分鐘快刷 | ~5 min | 6 | 60% SRS 到期 + 40% 反射維持（M≥85 的 R1–R3） |
| `daily15` | 每日訓練 | ~15 min | 12 | 35% 到期複習 + 40% 弱點 + 20% 新技巧 + 5% 拉高難度 |
| `deep45` | 完整 Session | ~45 min | 26 | 20% 熱身 + 30% 弱點 + 30% 主線推進 + 15% 難題 + 5% Boss |

時間估算用題目的 `timeLimit` 加總 × 1.35（含讀題與結算），不是固定題數。
**「15 分鐘也能完成一次有效訓練」的定義**：至少涵蓋 2 個弱點 skill 且至少 3 題到期複習。

### 配方 → 抽題

`BuzzPlanner.recipe(records, lengthKey, now)` 產出：

```js
{
  length: "daily15",
  estSeconds: 900,
  slots: [
    { role: "review",  count: 4, filter: { due: true } },
    { role: "weak",    count: 5, filter: { skills: ["integral.frullani","series.power.endpoint"] } },
    { role: "new",     count: 2, filter: { skills: ["integral.kings"], maxRank: 4 } },
    { role: "stretch", count: 1, filter: { minRank: 5 } }
  ],
  why: "Frullani 上週掉了 11 分，端點分析你標了 3 次「確定」但錯"
}
```

`BuzzSession.fill(recipe, problems, records)` 負責實際抽題，套用現有規則：
`RECENT_PROBLEM_COOLDOWN`(30)、`RECENT_STRONG_AVOID`(18)、難度上限、
**科目閘門**（見 4.7）、自訂題排除（週卷不得含自訂題）。

某個 slot 抽不滿時**降級而非留白**：`weak` 抽不滿→補 `review`→補同 family→補隨機。
降級路徑要寫進 `session.meta.fallbacks`，並在 CI fixture 中驗證各種空池情境。

### `why` 欄位是產品，不是 debug 訊息

每一個推薦都要能用一句話說出理由。使用者信任推薦系統的唯一來源是「它說得出為什麼」。
`why` 的組字規則寫在 `planner.js`，且有 fixture 驗證不會出現空字串或「undefined」。

> 　　　　 這裡不教你微積分，這裡讓你把已經學過的東西練到反射。
> 　　　　 · 1407 題，依技巧分類而不是章節
> 　　　　 · 會告訴你是「不會」還是「來不及」
> 　　　　 · 錯題自動排程回鍋，不是丟進倉庫
> 　　　　 [開始]
>
> 第 2 步  你現在在哪個階段？（決定起始難度，之後隨時可調）
> 　　　　 高中先修 / 大一微積分 / 期中期末要考了 / 想維持手感
>
> 第 3 步  先花 5 分鐘測出你的底
> 　　　　 [開始定位測驗] [直接開始練]
> ```
>
> **舊的第一屏是 5 個並列選項**（定位測驗 / 先暖身 / 照主線 / 直接挑戰 / 稍後）。
> 那不是「選一個起點」，那是把決策成本丟給一個還不知道這站在幹嘛的人。

> **定位測驗結束後只有一個出口**：「開始第一份訓練 · 15 分鐘 12 題」，

> 一個剛測完的人如果去逛題庫，多半就走了，而那正是 onboarding 完成率掉下來的地方。
>
> 跳過定位測驗時，用第 2 步的自陳給保守起點，並**老實說它是估的**：
> 「已用你選的階段設定起始難度。實際練幾局之後會自動校準。」

現況：`ONBOARDING_LEVELS` 三選一 + 8 題 `placement`。骨架在，但不是預設流程。

### 新流程（首次進站，不需要帳號）

```text
1. 一句話定位             「Buzz 是刷題健身房，練到反射為止」        [ 開始 ]
2. 你現在在哪              高中 / 大一微積分 / 期中考前 / 想維持     ← 決定 scope 與預設難度
3. 5 分鐘定位測驗          8 題自適應（現有 placement，PLACEMENT_START_RANK=2）
4. 結果頁                  「你落在 R3。最弱：級數端點分析」
                          ── 這一頁必須顯示第一份雷達 ──
5. 直接開始第一個訓練       [ 開始 15 分鐘訓練 ]
```

**硬規則**：

- 第 3 步可**跳過**，跳過則用第 2 步的自陳給一個保守起點（`difficultyCap = 2`）。
- 第 5 步是**唯一**的出口按鈕。不給「隨便逛逛」。
- 全程不超過 6 分鐘。
- **第一次進站永遠不會看到 1407 題的題庫頁。**
- 定位測驗結果寫進 `records.placement`（已有欄位）+ 觸發第一份 `plan`。

### 自適應規則（沿用並強化）

從 R2 開始；答對 → rank+1（上限 6），答錯 → rank−1（下限 1）；連續 2 題同 rank 答對直接 +2。
8 題後取最後 3 題所在 rank 的中位數為定位 rank。
另外記錄**最弱 family**（答錯最多的 family）寫入 `placement.weakTag`。

## 4.6 考試倒推

> **實作現況（2026-08-16，已上線）**
>
> 設定入口在「訓練 · 模擬」。`planner.examPlan()` 的計算早就寫好了，這一步補上 UI。
>
> 實測輸出（20 天後期中、每天 10 分鐘、全範圍）：
>
> ```text
> 考試倒推                                    20 天
> 微積分期中
> 範圍：全範圍 · 每天 10 分鐘 · 目標每個技巧 70 分
>
> 排不完。以每天 10 分鐘，到考前只顧得到 50 個技巧中的 33 個。
> 建議把每天加到 15 分鐘，或把範圍縮小。
>
> 交錯級數           差 45 分
> Wallis            差 44 分
> 三角與雙曲積分      差 44 分
> ```
>
> **這個功能唯一的價值就是那句「排不完」。** 假裝排得下，使用者考砸只會怪產品；
> 老實說做不完並給出具體數字（加到幾分鐘、顧得到幾個），那才是真的在幫忙。
> smoke test 專門守著這條線。
>
> 取消考試時**不刪除而是封存到** `records.planHistory` —— 考後報告要看得到當初的設定。
> 考試日過後首次開啟自動出報告（能力前後對比 + 最常犯的錯因），關掉後不再出現。

### 設定

使用者在「今天」卡的抽屜設定：

```js
records.plan = { examAt: "2026-11-05", label: "微積分期中", scope: ["integral.*","series.*"], dailyMinutes: 15 }
```

`scope` 可從預設藍圖選（期中 / 期末 / 轉學考 / Integral Bee），對應現有 `NAMED_EXAMS` 的組成。

### 倒推演算法

```text
D          = 距離考試天數
target     = 對 scope 內每個 skill 要求 M >= 70（Boss 級 scope 要求 60）
gap(s)     = max(0, target - M(s))
effort(s)  = gap(s) / 6          # 經驗值：每 6 分精熟度約需 1 次有效 session 的該技巧曝光
totalWork  = Σ effort(s)
dailyWork  = totalWork / max(1, D - 2)     # 保留 2 天緩衝
```

`dailyWork` 換算成題數後與 `dailyMinutes` 比較：

- 做得完 → 正常模式，每天配方偏向 `scope` 內技巧。
- 做不完 → 顯示誠實警告：「以每天 15 分鐘，到考前只能顧到 6 個技巧中的 4 個。
  建議加到 25 分鐘，或把 Green 定理放掉。」**並提供兩個按鈕：加時間 / 縮範圍。**
  絕不假裝做得完。

### 衝刺模式（T-7 自動切換）

- 配方改為 70% scope 內弱點 + 30% 到期複習，停止引入新技巧。
- 每天固定一份 10 題的 scope 限時模擬（Timed），用來餵 Pressure Accuracy。
- 首頁改顯示倒數與「今天必須清掉的 3 個技巧」。
- T-1：只做「自信但常錯」清單 + 一份完整模擬卷。

### 考後報告

考試日過後首次開啟，自動生成一頁：
起訖期間的能力變化、每個 scope skill 的 M 前後對比、練了幾題幾分鐘、
最大進步 / 最大退步技巧、以及「這段期間你最常犯的錯因」。可匯出成分享卡。

## 4.7 科目閘門的一般化

> **實作現況（2026-08-16）：改成不做閘門，改成移除。**
>
> 理科秒殺包（物理 90 + 化學 81）已從 BuzzCalculus 移除，題庫回到純微積分 1407 題。
> 原本的做法是留著理科題、靠一道閘門擋它不要跑進快速訓練 / 雷達 / 主線 ——
> 但那道閘門要在**每一條抽題路徑上重複防守**，每加一個新功能就要記得再擋一次。
> 實作能力模型與 planner 時，光是 `subject: "science"` 的過濾就散在 4 個地方。
>
> 理科的家是姊妹站 BuzzPhysics。移除之後守的規則從「理科不能污染微積分」
> 變成更簡單也更強的「**這個題庫只有微積分**」，由 `tools/validate_calculus_only.js` 鎖住
> （取代原本的 `validate_science_gate.js`）。
>
> kernel 裡的 `subject` 機制**保留** —— 之後 kernel 要和 BuzzPhysics 共用，
> 那時它才會真正派上用場（見 [08.1](08-platform.md#81-從-app-到-engine)）。

現況：`SCIENCE_TOPICS` / `SCIENCE_PACKS` 兩個 Set + `calculusOnly()` + `scienceRequested()`，
由 `tools/validate_science_gate.js` 在 CI 鎖住「理科題不得污染微積分主線」。

**這個機制是對的，要保留並一般化**，因為未來會有線代、統計、機率。

```js
const SUBJECTS = {
  calculus:  { topics: ["limits","derivatives","integrals","series"], primary: true },
  science:   { topics: ["physics","chemistry"], packs: [...] },
  linalg:    { topics: ["matrix","eigen"], packs: [...] }   // 未來
};
```

規則升級為：**任何非 primary subject 的題目，只有在使用者主動選擇該 subject 的 topic 或 pack 時才進池。**
`validate_science_gate.js` 改名 `validate_subject_gate.js`，改成遍歷 `SUBJECTS` 而非寫死物理化學，
並涵蓋所有新增的自動流程（今日訓練、sprint5、考試倒推、SRS 複習）。

## 4.8 答題體驗

### 三層提示

> **實作現況（2026-08-16）**：三層結構原本就有，這一步修的是**第二層在說謊**。
>
> `hintsFor()` 對沒有作者提示的題目會回傳 topic 級的泛用文字
> （「先觀察是否能換元」）。那當第一層「給方向」可以，但它原本被當成第二層
> 「關鍵步驟」端出去 —— 那是在假裝我們知道這題怎麼解。
>
> 現在第二層**只吃作者親自寫的提示**（1407 題中有 709 題）。沒有的題目老實說
> 「這題還沒有寫專屬的關鍵步驟，直接看完整推導，別在這裡浪費時間」。

```text
Level 1  只給方向        「這是兩個指數相減除以 x」        扣 4 分
Level 2  給關鍵技巧      「Frullani，先確認兩端點極限」     扣 8 分
Level 3  完整解法        全部步驟                          該題不計精熟度（assisted）
```

現況 `hintsFor()` 對沒有作者提示的題目回傳 **topic 級泛用文字**（886/1407 有作者提示）。
泛用文字當 Level 1 可以，但**不能當 Level 2**。

**規則**：Level 2 必須是題目專屬。沒有作者 Level 2 的題目，提示只開放到 Level 1 與 Level 3。
CI 統計覆蓋率並在 README 顯示，目標 P3 結束時 R4+ 題目的 Level 2 覆蓋率 100%。

### 「這題真正關鍵是什麼」

> **實作現況（2026-08-16）：覆蓋率 1407/1407（100%）。**
>
> 原設計是「R3+ 必填」的人工欄位。1407 題人工撰寫一句話不現實，所以改成兩層：
> 作者有寫就用 `problem.keyIdea`；沒寫就**從 skill graph 推導**
> （「這題考的是 Frullani 積分 + 瑕積分」）。
>
> 推導不是唬爛：skill graph 有 100% 覆蓋率且經過 CI 驗證，「這題考什麼技巧」是
> 查得出來的事實 —— 而這個產品本來就是在教「看到題目該用哪個工具」。
>
> 顯示在結算後，**答對答錯都顯示**：答對的人確認自己是看出來而不是猜對，
> 答錯的人拿到一句記得住的話。

`keyIdea` 一句話，在**結算後**顯示（不是答題中），無論對錯都顯示。
這是整個產品裡最便宜、最有效的教學元件。R3+ 題目必填。

### 多解法

`altSolutions[]`，只對 R4+ 提供。UI 用分頁：`解法 A｜解法 B`。
每個解法標上「適合的情境」（考場最快 / 最容易記 / 最一般化）。

### 自動存檔

> **續傳實作現況（2026-08-16，已上線）**
>
> 一份 12 題模擬考的存檔只有 **1043 bytes**。存檔時機：每答完一題（立即）+ 計時器每 10 秒（節流）。
>
> 三個實作上的關鍵決定：
>
> 1. **quiz 物件不能直接 `JSON.stringify`。** 它帶著題目的完整參照
>    （每題含 prompt / solution / hints），直接存會膨脹幾十倍。存的時候換成 id，
>    讀的時候從題庫接回來。題目下架時該局作廢而不是丟例外。
> 2. **草稿筆畫不存。** 使用者要的是「題目和答案還在」，不是「我畫的線還在」，
>    不值得為它撐爆 localStorage 額度。
> 3. **大考的整份倒數照實走，日常模式重啟單題計時。** 前者是考試誠信
>    （中斷的時間不會還給你），後者不為難使用者 —— 呼應 [00 的 P4 原則](00-north-star.md#p4-焦慮只准存在於考試模式)。
>
> **實測時抓到一個真 bug**：`index` 只在按「下一題」時才推進，所以在回饋畫面
> 中斷時 `index` 會落後 `answers` 一格。不補這一步的話，續傳會讓使用者
> **重新作答已經答過的那題**，`answers` 出現重複、分數算兩次。
> 現在 smoke test 直接斷言「3 筆作答時 index 必須是 3」。
>
> 中斷次數寫進 `history[].interruptions` —— 一份中斷過的考卷，成績的意義本來就不一樣。
> 離開首頁**不清除**續傳（離開不等於放棄），只有結算或按「放棄」才清。

**現況風險**：模擬考中途重新整理 = 整份消失。這是必修項。

```js
localStorage["buzzcalculus.session.active"] = {
  quiz: <可序列化的 quiz 狀態>, savedAt, schema: 1
}
```

- 每答完一題 + 每 10 秒 寫入一次（節流）。
- 計時器狀態存**絕對截止時間戳**而非剩餘秒數，重整後正確扣掉離開的時間。
- 重開站台時若有未完成 session 且 `savedAt` 在 6 小時內，首頁跳「繼續上次的訓練？」。
- 考試模式的續傳要誠實：顯示「這份考卷已中斷過一次」，並記錄在 history。
- 結束或放棄時清除。

### 輸入與無障礙

> **實作現況（2026-08-16，已上線）**
>
> - **鍵盤 7 組快捷鍵**：1–4 選項、Enter 送出/下一題、空白鍵下一題、H 提示、
>   S 跳過、Esc 離開、? 顯示快捷鍵表。正在輸入時（input / textarea / contenteditable）
>   一律不攔截，否則使用者打 h 會變成叫出提示。
> - **KaTeX 輸出 `htmlAndMathml`**：螢幕閱讀器讀得到數學，而不是一串無意義字元。
>   MathML 用 clip 視覺隱藏，不影響版面。
> - **全域 `:focus-visible`**：3px 外框，深色模式換金色（藍色在深色下對比不足）。
>   用 `:focus-visible` 而非 `:focus` —— 滑鼠點擊不該留下外框。
> - **計時器 `role="timer" aria-live="off"`**：不加的話螢幕閱讀器會每秒朗讀一次倒數，
>   整個產品對視障使用者直接不可用。
> - **跳到主要內容**：不用 tab 過整條導覽列。
> - **`prefers-reduced-motion`**：尊重系統的減少動態效果設定。

- **鍵盤完整可用**：`Enter` 送出、`1-4` 選項、`H` 提示、`Space` 下一題、`Esc` 離開、`?` 快捷鍵表。
  現有 `WEBWORK_KEY_GROUPS` 鍵盤面板保留，但**滑鼠不得是唯一輸入途徑**。
- **focus state**：所有可互動元素必須有 `:focus-visible` 外框，對比度 ≥ 3:1。
- **語意**：計時器 `role="timer" aria-live="off"`（避免螢幕閱讀器每秒朗讀），
  結算訊息 `aria-live="polite"`，題目區 `role="group" aria-labelledby`。
- **KaTeX 無障礙**：開啟 `output: "htmlAndMathml"`，讓 MathML 提供給輔助科技。
- **iPad**：Apple Pencil 草稿區（`renderScratchboard` 已存在）→ 加壓感、橡皮擦、
  兩指還原、與答案區左右分欄。手寫辨識**不在此期範圍**（見 [08](08-platform.md)）。
- **手機**：題幹與輸入框永遠在第一屏；鍵盤面板預設收合（`quiz.keypadOpen` 已有此邏輯，保留）。
