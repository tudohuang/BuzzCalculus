# 00 — North Star：Buzz 要長成什麼

## 一句話定位

**Buzz 是 STEM 的健身房，不是線上課程。**

課程賣「講給你聽」。Buzz 賣「練到反射」。這條線決定了所有取捨：
凡是把使用者變成觀眾的功能都往後排，凡是讓使用者多做一題、做得更準、知道自己哪裡爛的功能都往前排。

## 核心迴圈

```text
學過  ->  大量練  ->  錯誤診斷  ->  練到反射
             ^                        |
             +------------------------+
```

產品的每一個畫面都必須能回答：**「這一步讓使用者更靠近哪一段迴圈？」**
答不出來的畫面就是要收納的畫面。

## 五年形狀

```text
                    Buzz Account (一個帳號)
                    Buzz Pro     (一個訂閱)
                          |
        +-----------------+------------------+
        |                 |                  |
   BuzzCalculus      BuzzPhysics        下一個科目
   (旗艦 / 成熟)      (第二旗艦)         線代 / 統計 / ODE / 離散 / 機率
        |                 |                  |
        +--------- 共用能力訓練引擎 ----------+
                 (skill graph / session engine /
                  SRS / 難度校準 / 診斷)
```

微積分先跑通留存，才開下一個科目。**不允許在 Calculus 的 D7 留存指標達標之前開新科目。**
這是 B 區第 100 條，也是整份 spec 唯一的硬性排序約束。

## 產品原則

### P1. 難度語言是自有品牌

R1–R6 必須成為使用者自己會講的話（「這題大概 Buzz R5」）。
因此：

- 每一題的 rank 必須有 rubric 可解釋，不能只靠作者直覺。
- 名校名稱（MIT / Putnam / 東大）在**公開核心 UI 逐步淡出**，只保留在題庫詳情的「來源」欄位。
- 權威來自「你在 R4 的正確率是 68%」，不是來自「這題出自某校」。

現況：`source` 欄位已有 1327 題，但值多半是內部 pack 名稱（`Buzz core expansion pack`）而非學校名，
真正的名校字樣集中在 `東大`(16)、`World university & competition pack`(99)、`Putnam ...`(36)。
淡出成本低，見 [05-content-pipeline.md](05-content-pipeline.md#54-來源與原創聲明)。

### P2. 診斷比分數重要

「正確率 72%」是無用資訊。有用的是：

- 你是**不會**還是**來不及**（wrong vs timeout — 現有 `answers[].unanswered` 已經記了）
- 你在**不限時**會、在**限時下**垮（Untimed vs Pressure Accuracy）
- 你**自信但常錯**的技巧（confidence calibration）

### P3. 錯題是救援系統，不是倉庫

進錯題本的題目必須有出路：排程回來、被歸因、被轉成訓練任務。
一個永遠只增不減的錯題清單是產品失敗。

### P4. 焦慮只准存在於考試模式

整份倒數、無提示、突然死亡（`suddenDeath`）這類高壓規則**只能**出現在
「模擬考」與「挑戰」兩個分類。日常練習與每日訓練不得製造焦慮。

**監考類的規則已經整組移除（2026-08）。** 全螢幕鎖定與切頁判錯的立場是
「假設使用者會作弊，所以要盯著他」，但這是一個自己練給自己看的工具 ——
想查答案的人本來就查得到，被判錯只會讓他覺得被冤枉。它防不了任何東西，
卻會誤傷接一通電話、在 iPad 上被通知蓋掉、或者只是想開計算機的人。

壓力可以來自時間與難度，不能來自監視。

### P5. 資料是使用者的

紀錄可匯出、可刪除、可帶走。上雲之前，匯出 JSON 就是使用者的所有權證明。

## 明確不做的事（Non-goals）

寫下來是為了以後有人提案時可以直接引用拒絕。

| 不做 | 理由 |
| --- | --- |
| 引入前端框架（React/Vue/Svelte）重寫 | 現架構零 build、離線可用、載入快。重寫的收益是開發爽度，不是使用者價值 |
| 讓 LLM 直接產生題目答案或解析並上線 | 答案錯誤是這個產品的致命傷。AI 只能建立在可驗證的 symbolic / numeric result 上 |
| 做影片課程、直播、聊天式家教 | 那是課程產品，不是健身房 |
| 在 Calculus 留存跑通前開第三個科目 | 見上 |
| 預設公開的排行榜 / 個人成績 | 排行榜一律 opt-in |
| 為了「多一個玩法」而加模式 | 現在模式已經過多，P1 的工作是收納不是擴張 |
| 逼使用者註冊才能練 | 匿名可用是取得第一次體驗的關鍵 |
| 擬人化吉祥物、AI 對手取暱稱、RPG 用語（「開打下一格」「金關」） | 目標使用者是要付費的大學生。
把產品做得像手遊會讓「這值得付錢」變得難以說服。2026-08 已移除吉祥物心情、宿敵「小積」、RPG 用語 |
| 「你用了某個功能」型的成就（黑板使用者、Proof Reader） | 那不是成就，是操作紀錄。
成就只留代表「真的變強」或「真的持續在練」的里程碑（2026-08：23 → 10） |

## 成功長什麼樣

**產品層**

- 新使用者第一次進站 5 分鐘內完成一次有效訓練，並看到自己的定位。
- 老使用者打開首頁不需要思考，只要按一個按鈕。
- 使用者會說得出自己「哪個技巧爛」，而不只是「我微積分不好」。

**行為層（見 [09-roadmap.md](09-roadmap.md#指標)）**

- D1 / D7 / D30 回訪
- 每週有效訓練次數（>= 8 題且完成）
- 錯題回收率（進錯題本後 14 天內被答對的比例）
- R3 題平均反應時間的個人變化

**終極**

> 學生不是因為考試才打開 Buzz，而是像健身一樣固定回來維持數理能力。
