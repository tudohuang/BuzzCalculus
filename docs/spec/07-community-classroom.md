# 07 — 社群、教師、賽季

這一章的功能**全部依賴後端**（[06](06-identity-sync-legal.md)），因此排在 P5。
但資料模型要在 P3 就先定好，避免之後改 schema。

## 7.1 題目投稿

### 流程

```text
投稿表單 ──> candidate 區 ──自動檢查──> 人工複審 ──> live
                  │                        │
                  └─ 未通過 ────退回 ───────┘
```

**投稿不直接進公開題庫。** 這是不可協商的 — 題庫品質是唯一護城河。

### 投稿必填

| 欄位 | 說明 |
| --- | --- |
| `prompt` | LaTeX 題幹 |
| `answer` + `answerKind` | 答案 |
| `verify` | 可求值的驗證表達式（numeric / expression 必填） |
| `solutionSteps` | 至少 2 步的解析 |
| `keyIdea` | 一句話關鍵 |
| `origin` | 原創 / 改編 / 靈感 + `ref` |
| `skills` | 至少 1 個 skill 節點 |
| `rubric` | 三軸自評 |

### 自動檢查（投稿當下即時回饋）

1. KaTeX 可 render。
2. `verify` 與 `answer` 數值一致（[05.3](05-content-pipeline.md#53-答案驗證)）。
3. 自己的判分器判自己為正確，且 3 種等價寫法都通過。
4. 重複偵測（[05.5](05-content-pipeline.md#55-重複偵測)）— 命中時直接顯示「這題很像 #417」。
5. `origin` 合規檢查（名校詞彙規則）。

四項全過才進人工佇列。**這一步把 90% 的低品質投稿擋在系統外，且不需要人力。**

現有的 `src/custom_problems.js`（localStorage + `#pack=` 分享）就是投稿表單的前身，
UI 幾乎可直接沿用，只是把「存到本機」改成「送出審核」。

### Curator 制度

| 等級 | 門檻 | 權限 |
| --- | --- | --- |
| 投稿者 | — | 投稿進候選區 |
| 認證作者 | 5 題 live 且平均評價 >= 4.0 | 投稿跳過初審，直接進人工佇列前段 |
| Curator | 20 題 live、無 quarantine 紀錄、被推薦 >= 50 次 | 可複審他人投稿（雙人同意才 live） |
| 教師認證 | 人工授予 | 可為題目掛「教師認證」標章 |

作者頁：`/author/<handle>` 顯示題目列表、
「你的題被作答 18,430 次」、平均評價、被收藏數。這是投稿的主要動機來源。

**Verified Buzz Problem 標章**條件：通過全部自動檢查 + 兩位 curator 複審 +
作答數 >= 500 且 quarantine 回報率 < 0.5%。

### 社群評價

答完題後可給 1 個輕量訊號：`好題` / `題目有問題`（後者導向回報流程）。
不做 5 星評分 — 太重，回填率會很低。「好題率」= 好題數 / 作答數。

## 7.2 班級與教師

### 模型

```text
Class { id, name, teacherId, joinCode, subject, createdAt, memberIds[] }
Assignment { id, classId, packRef, dueAt, timed, hintsAllowed, mode }
```

`packRef` 可以是：既有 pack key、uid 清單、或一份 skill 條件（`skills + rank 範圍 + 題數`，
由 session 引擎當場抽題 — 這樣每個學生的題目不同，減少抄答案）。

### 教師視角

| 畫面 | 內容 |
| --- | --- |
| 班級總覽 | 完成率、平均正確率、平均耗時 |
| **全班 skill heatmap** | skill × 學生的矩陣，紅 = 弱。這是老師最想要的東西 |
| 全班都錯的題 | 依 `錯誤率 desc` 排序，直接告訴助教下週要講什麼 |
| 個別學生 | 該生的能力雷達與錯因分佈（**只有加入班級的學生資料可見**） |
| 派模擬考 | 用 named exam 或自訂條件，設時間窗 |

### 隱私邊界（硬規則）

- 學生加入班級 = 明示同意分享「該班級指派作業的成績」給老師。
- **不分享**班級外的練習紀錄、不分享完整 records。
- 學生可隨時退出班級，退出後老師只保留已提交的作業成績。
- 學生端永遠看得到「老師能看到什麼」的清單。

## 7.3 排行榜與 Duel

### 排行榜

**預設 opt-in，永遠 opt-in。** 未開啟的使用者不出現、也看不到自己的名次。
範圍：班級 / 學校 / 全站。顯示化名（使用者自訂 handle），不顯示 email。

### 非同步 Duel

```text
Duel { id, packSnapshot: uid[10], challengerId, opponentId,
       results: { [userId]: { correct, totalSec, at } }, expiresAt }
```

- 兩人做**同一組 10 題**（快照固定，公平）。
- 非同步：發起後 48 小時內完成即可。
- 勝負 = 正確數優先，同分比總秒數。
- 現有的「宿敵小積」（`records.rival`，AI 對手、level 1–10）是這個功能的單機版原型，
  速度公式與 UI 可直接沿用，把 AI 換成真人的歷史成績。
- 反作弊：Duel 一律 Timed、無提示、記錄每題耗時，異常快（< 人類下限）標記不計入。

## 7.4 Boss 與賽季

| 機制 | 說明 |
| --- | --- |
| **每週 Boss** | 每週一換一題 R6。全站同一題（沿用 `daily_one` 的日期種子機制，改成週種子） |
| **首殺紀錄** | 該週第一個答對的人（顯示化名 + 秒數），永久留在 Boss 檔案館 |
| **Boss streak** | 連續幾週答對每週 Boss |
| **Integral Bee 賽季** | 一季 8 週，每週一份 12 題限時卷，積分累計，季末總排名 |
| **Buzz Season** | 年度：四個 Integral Bee 賽季 + 期末總決賽。有賽季徽章 |
| **校際挑戰** | 學校為單位的平均分（需要學校標記 — opt-in 且不驗證，只當標籤） |

**設計約束**：所有競賽內容都在 `challenge` bucket，永不影響日常訓練配方。
使用者完全不參加任何競賽也應該有完整的產品體驗。

## 7.5 題包分享（可以現在就做）

這一組**不需要後端**，現有 `custom_problems.js` 的 `#pack=` 機制已經支援。

| 功能 | 做法 |
| --- | --- |
| 分享碼 | 現有 base64 編碼的 `#pack=` |
| QR code | canvas 自繪（不引 CDN），約 150 行 |
| 限時設定 | pack meta 加 `timeLimit` 覆寫 |
| 提示開關 | pack meta 加 `hintsAllowed` |
| 難度標示 | 由題目 rank 自動計算並顯示 |
| 直接開始 | 開連結後首屏就是「開始」按鈕，不列出題目 |

分享碼長度問題：純自訂題會很長。改成「只帶 uid 清單」的模式（引用既有題庫）時
碼會非常短，適合口頭 / QR 傳遞。兩種模式都支援：`#pack=`（含題目）與 `#set=`（只有 uid）。
