# 白話證明（proof language）

一行一句、可以在瀏覽器裡被檢查的證明語言。沒有後端、不用 Lean。

## 它檢查什麼、不檢查什麼

三個引擎，各自誠實：

| 引擎 | 做什麼 | 綠 | 黃 | 紅 |
|---|---|---|---|---|
| 句型 | 認得每一句在做什麼（13 種句型） | 認得 | — | 讀不懂 |
| 代數 | `A = B ≤ C < D` 在目前假設下隨機取 160 個點驗 | 每段都成立 | 含未知符號（抽象 f、`lim`） | 某段不成立（附反例） |
| 推論 | 規則字典（16 條：MVT、三角不等式、夾擠、AM-GM…）比對句子形狀 | 形狀對上 | 引用了但形狀對不上 | — |

再加一層**骨架**：ε-δ 要有「任取 ε、取 δ、假設 |x−a|<δ、推到 |f(x)−L|<ε」；歸納要有基底、歸納假設、從 k+1 左式走到右式的鏈；分情況每一種都要走到目標再總結；反證要有反設與矛盾。

「數值上成立」不等於「推導出來」。一條關係式要**接得上**（2026-09-14 收緊）：鏈的一端是已知的東西——前面出現過的式子、宣告過的變數或定義、抽象 atom、自訂函數代常數（g(0)）、或題目目標的一邊／ε-δ 的起點／歸納 k+1 的左式（只當多段鏈的**起點**，而且第一段不能就是目標本身）；或第一段是顯然的起點；或跟前面某條關係式**移項後成正比**（同號不夠——兩條剛好都成立的不等式當然同號）。純數字永遠不算已知。A = A 的段是紅的；一條鏈裡方向不一致（≥ 之後又 ≤）是紅的。

**顯然的起點**由一個小的符號正負引擎判定（`parseTree` + `signOf`）：常數、平方／偶次方、絕對值、根號、e^x、題目說了 ≥ 0 或 > 0 的變數、以上的和與積、正數除以正數；`L ≥ R` 看 `L − R`（R 是 0，或 R 是常數 c 而 L 是「… + c」）。`x² + 1 ≥ 2x` 不顯然——要先寫 (x − 1)² ≥ 0。

**因為 P，所以 Q**：P 要立住——字面或等價於某條條件（題目給的、假設、情況、宣告的範圍）、前面驗過的關係、存在句給的關係、題目的佔位符事實（f′(_) = 0）、顯然的起點、或只由定義與常數組成（δ ≤ 1 而 δ = min(1, ε/7)）。立住的 P 的式子之後算已知。Q 照一般規則接地。

**語法**：一行一句（句號只能在最後）；沒有句型的裸關係式是紅的（它是推導、引入還是條件，要說）；式子裡沒宣告的符號、混進去的中文都是紅的，不是黃的。分情況裡，一段要有自己的條件或推過一條鏈才能下結論（「否則」那一段什麼都沒推就寫結論，不算）；「重述目標」只在同一段內成立。

整篇結論四種：**verified**（全綠、骨架齊）、**partial**（有黃）、**incomplete**（缺骨架）、**broken**（有紅）。

## 句型

| 句型 | 例 |
|---|---|
| 任取／設／取／令（Let / Fix / Take） | `任取 ε > 0。`、`取 δ = ε/3。`、`設 x, y 為實數。` |
| 假設／若…則…（Assume / If … then） | `假設 0 < \|x − 2\| < δ。` |
| 則／所以／展開得／整理得（Then / Hence） | `則 \|3x − 6\| = 3\|x − 2\| < 3δ = ε。` |
| 由 <規則>，… （By …） | `由三角不等式，\|x + y\| ≤ \|x\| + \|y\|。` |
| 由泰勒定理，存在 ξ ∈ (x, x+h) 使 f(x+h) = f(x) + h f′(x) + (h²/2) f″(ξ) | 泰勒（Lagrange 餘項）是規則 17；前提是「f 二次可微」（文字事實 `twice-differentiable`）。等式對某個未定義的 atom 是一次的，就解出來當定義（`solveLinear`：E(0)、E(1)、E(2) 驗一次性） |
| 由 <定理>，存在 c ∈ (a, b) 使 …（存在句） | `由平均值定理，存在 c ∈ (x, y) 使 f(y) − f(x) = f'(c)(y − x)。` — c 變成在 (a, b) 取樣的變數，關係式登記成條件；定理的前提（MVT 要可微、IVT 要連續＋兩端異號）必須在前面出現過 |
| 令 g(x) = …（自訂函數） | `令 g(x) = x⁵ + x − 1。` — 本體只能用參數、常數、內建函數 |
| 文字事實 | `g 是多項式。`、`f 在 I 上連續。`、`f 可微。` — 用鍵登記（`continuous:f`），定理前提查它。自訂的 g 若由多項式與 sin、cos、exp（連續再加 abs）加減乘組成，連續／可微直接認；抽象的 f 要題目 `facts` 給 |
| 因為…，所以…（Because …, so …） | `因為 1 + h ≥ 0，所以 (1+h)^(k+1) ≥ (1+kh)(1+h)。` |
| 分情況／情況一：條件（Case 1:） | `分兩種情況。`、`情況一：x + y ≥ 0。`、`情況二：否則。` |
| 用歸納法／當 n = 1 時／假設 n = k 時成立 | `當 n = 1 時，左式 = 1，右式 = 1，成立。` |
| 反設／矛盾 | `反設 m 是最大的實數且 m < 1。`、`這與 m 是最大的矛盾。` |
| 故／得證 | `故 \|x + y\| ≤ \|x\| + \|y\|。` |

中文關鍵字後面可以不空格（`因為x>0，所以x²>0`、`任取ε>0`）；`因為 g 連續，所以由中間值定理，存在 c 使 …` 這種結論自帶定理的句子也認。數學用作答同一套 ASCII；`ε δ √ ≤ ≥ ≠ ² ³ ⁴ ⁵ ⁿ ∈ ∞` 與希臘字母、全形標點都會被正規化。`3x`、`k(k+1)`、`2kh` 這種隱式乘法看得懂；`1 + 2 + ... + n` 由題目的 macro 轉成可算的和。數列極限把 δ 換成 N（`bound.threshold: "N"`），骨架變成「任取 ε、取 N、假設 n > N、推到 |a_n − L| < ε」。

### 抽象函數怎麼驗

`f(y)`、`f'(c)` 這種算不出來的東西不再一律標黃：spec 的 `abstract` 把 f、f′ 宣告成**不透明的取樣變數**（atom），同一個寫法永遠是同一個變數。所以「存在 c 使 f(y) − f(x) = f'(c)(y − x)」登記之後，後面的「f(y) − f(x) = 0」就能在同一批取樣點上驗。題目給的「對所有點成立」的條件寫成佔位符（`facts: ["f'(_) = 0"]`），使用者寫出「因為 f'(c) = 0」才會被拿來用。

反證的矛盾只認三種算得出來的：抽不到點、某關係式對所有樣本皆假、「m 是最大／最小的」配一條驗過的 `t > m`（證人也要滿足反設的條件，不能拿 −1 冒充正實數）。

- `src/proof_lang_content.js` — 題目 spec（`BUZZ_PROOF_LANG_PROBLEMS`，43 題、五族、R1–R3；最後兩題是經典解析習題（導數有界、某處 |f″| ≥ 4），用泰勒＋atom 撐起來的抽象 f 證明）與九課教學（`BUZZ_PROOF_LANG_LESSONS`；1–5 初學路線、6–9 高手路線，第 9 課是抽象函數與泰勒）。`source` 欄位會顯示成標籤。
- `tools/validate_proof_lang.js` — 每題參考證明必須全綠；刪掉任一非 optional 行不能還全綠；翻符號要紅；一行寫目標不能全綠。嚴格語法九個案例釘住（A = A、因為目標所以目標、裸關係式、沒宣告的變數、方向不一致、一行兩句、第一段就是目標的鏈、顯然／不顯然的前提）。課程：範例全綠、練習的起手式是參考證明的逐行開頭、起手式不能有紅也不能已經全綠。
- `tools/e2e_proof_lang.js` — 畫面：即時三色、範本插入、錯 δ 紅在第 4 行、草稿存活。

## spec 欄位

```js
{
  id, family, title, difficulty, statement, prompt (TeX),
  vars: { x: { min, max, int? } },      // 取樣範圍
  given: ["a >= 0"],                     // 題目給的條件
  functions: { S: (n) => … },           // 可算的和之類
  abstract: { f: { min, max }, "f'": { min, max } },   // 驗不了的函數 → 不透明取樣變數
  facts: ["f 在 I 上可微", "f'(_) = 0"],  // 題目給的文字事實；`_` 是佔位符（對所有點成立）
  macros: [{ pattern, replace }],        // 「1+2+...+n」→ S(n)
  goal: { relation: "S(n) = n*(n+1)/2" } | { text: ["lim_{x->2} 3x = 6", …] },  // lim 各種寫法收斂成同一個鍵
  bound: { lhs: "abs(3*x-6)", rhs: "eps", threshold?: "N" },   // ε-δ 的收尾鏈兩端；數列極限的門檻變數
  induction: { variable: "n", base: 1 },
  skeleton: "epsilon-delta" | "induction" | "cases" | "contradiction" | "direct",
  reference: ["…", "…"],                // 參考證明
  optional: [0],                        // 刪了也該還全綠的行（宣告、標籤、可跳過的一步）
  allowUnsure: true,                    // 允許 partial 算完成（保留給真的驗不了的題；目前 41 題都全綠，沒有題用到）
  coach: "…"
}
```

## 已知邊界

- `lim` 本身算不出來：夾擠定理只比對形狀（要先有 −g ≤ f ≤ g 的鏈，`requires: sandwich`），結論那句靠字面對目標。
- 數論（√2 無理、整除性）沒有可取樣的關係式，寫不成題。
- 抽象函數的等式解不了又抽不到點時（`g(c) = 0`）只記成「主張過的關係」，之後字面、等價或移項後（`cos c = c`）引用它才算。
- `≠` 在連續取樣下幾乎永遠成立，所以「f′ ≠ 0 ⇒ f 一對一」這類題釘不住（刪掉關鍵步驟還是全綠），沒收進題庫。
- 反證只認實數上的最大／最小：整數的「t = m + 1 也是整數」與 `x² + 1 = 0` 這種抽不到點的反設，算不出矛盾。
- 取樣是機率式的：等式看差、不等式看方向，160 個點；極端邊界（等號成立的單點）靠容差。
- 抽不到樣本不代表假設不可能成立，不會被當成反證。

## Proof Input v2：自由書寫層（2026-09-19）

引擎不學自然語言；自然語言先被翻成引擎已經會的句型語言。`src/kernel/proof_surface.js` 站在 `proof_lang.js` 前面：

1. 保護數學區塊：`$…$`、`(…)`、`$$…$$`、`[…]`，區塊內的換行不是句子界線；沒配對的分隔符與 align 環境標黃並說明。
2. 切段落與句子：句號、！？；、空行、單一換行（上一行以連接詞或逗號收尾、或下一行是數學區塊時不切）；省略號與小數點不是句號。
3. 一句可以有好幾個動作：`Choose δ = ε/3 and suppose 0 < |x−2| < δ` 拆成「取」「假設」；`給定任意 ε>0，我們選 δ=ε/3` 拆成「任取」「取」。
4. 英文與中文同義句都映射到同一個句型：Let … be given／任取，Choose／Set／取，Suppose／假設，Then／Hence／則，By the MVT／由，Since A, we have B／因為…所以，Base case／當 n = 1 時，Suppose it holds for n = k／假設 n = k 時成立，Case 1／情況一，Suppose for contradiction／反設，QED／得證。
5. 每一個動作記住原文的 sourceRange；報告映回原文，一句多動作時標出「第 i / n 段」。
6. 三色語意不變。翻譯層只多做一件事：讀不出是哪種動作的句子標黃（不猜、不放行），紅只留給「理解了而且驗證失敗」。

舊格式（一行一句、中文句型開頭）翻譯後一字不改，`tools/validate_proof_surface.js` 釘住：43 題參考證明經翻譯層判定與逐句顏色不變、同一證明的六種寫法全綠、五種等價寫法不變、五種壞寫法標黃、翻符號仍紅在同一句。

編輯器上方可以切「自由書寫／引導句型」；引導句型直接餵引擎（原本的行為）。

## Proof Input v2.2：Goal Semantics + Transformation Grounding（2026-09-19）

核心一句話：**「是真的」和「是由前面推出來的」是兩件不同的事。** 數值引擎回答第一個；這一版開始回答第二個。

### 語意目標
- 題目自己帶一個語意目標（`specSemanticGoal`）：由 `goal.text` 的 lim 形式與 `bound` 算出 `{ kind: "limit", variable, point, functionExpr, value, proofForm: { kind: "epsilon_delta", neighborhood, target } }`。
- 使用者的「We want to show that …／我們要證明 …」翻成 goal 節點，`parseSemanticGoal` 讀成同一種物件：lim 形式、∀ε∃δ 形式（`quantified: true`）、或一般關係式。
- `goalEquivalent` 不是字串比對：lim 形式 vs ∀ε∃δ 形式比的是點與 `|f(x) − L|`。對得上綠（「已辨識證明目標：…」「已辨識為 ε–δ 極限目標」）；**對不上紅**（「你宣告的證明目標與題目不同。題目：…；你寫：…」），整份 broken；讀不出是哪種命題才黃。
- 沒寫目標句照樣能完成；結尾的 `lim … = L` 不拿去取樣，對上目標且骨架齊時說「結論與原證明目標一致。ε–δ 證明骨架完整」，規則記成 `epsilon_delta_definition`。

### 接地的優先序（每一句推導）
1. 直接引用：前面已經有一模一樣的關係。
2. 代數等價：移項、同乘正數（`equivalentLink`，回報對上的那一條）。
3. 改寫規則（`TRANSFORMATIONS`）：`|x−a|<r ⇔ a−r<x<a+r`（更寬的常數區間算「由目前條件推出，不是等價改寫」）、傳遞 `A<B、B≤C ⇒ A<C`、區間裡的界（x 被夾在 a<x<b 時把 E(x) 掃一遍）、三角不等式。
4. 定理字典（由 <定理>，…）。
5. 只有數值成立而找不到來源：**黃**，訊息「在目前條件下成立，但找不到它是由哪一步推出的」。

### Provenance
每一條登記的關係（假設、前提、驗過的鏈）記進 `ctx.factLog`：`{ id, expr, line, provenance: { kind, rule, from } }`；報告帶 `facts` 與每行的 `grounding`，畫面之後可以做「這一步從哪裡來」。

驗收證明（lim x² = 9 的九段英文＋LaTeX）與變異（1<x<5 綠但註明由條件推出、3<x<4 紅、目標寫成 8 紅、憑空真話黃）由 `tools/validate_proof_surface.js` 第 5 節釘住。
